BingoGoals

Android · Kotlin + TypeScript v0.1 · closed testing on Google Play

Turn your goals into a bingo card and call a line every time you hit one.

A native Android app to build bingo cards from your New Year, summer, travel or any-occasion goals: stamp each goal you hit, call a line and celebrate the full card. It began as a Flutter prototype, became an installable web app with a NestJS API, and is now a Kotlin and Jetpack Compose app.

  • 3×3, 4×4 or 5×5
  • Ideas for every occasion
  • No account

03 What I built

  • Native Kotlin and Jetpack Compose app with Room and DataStore, plus a pure Kotlin :domain module with the bingo rules.
  • Screenshot tests in Spanish and English and in light and dark themes; the screenshots on this page come from them. 84 tests in the Android app.
  • Creating a card: occasion, size (3×3, 4×4 or 5×5) and style. If your goals don't fill the card, it is completed with ideas for the occasion.
  • Share the card as a square image or a story, with the option to hide squares.
  • Release build signed with a key kept outside the repository and a privacy policy linked from Settings.
  • The web version is still deployed: a React PWA on IndexedDB and a NestJS, Prisma and PostgreSQL API with accounts and sync, which will be the app's server.
  • Vitest, Testing Library and Playwright on the web, CI on every pull request and a code review at the end of each phase.

04 Decisions and why

  1. Native Kotlin instead of wrapping the web app with Capacitor. The widget, ads with EU consent and the 60 fps stamp animations needed native code anyway.
  2. The bingo rules live in a pure Kotlin module (:domain), ported from the web version along with their tests. They run in milliseconds, with no emulator.
  3. Screenshot tests on top of logic tests. They catch visual changes across both languages and themes, and give always-current screenshots as a bonus.
  4. Local first: cards live on the phone and an account is optional. The API already serving the web app will provide sync when it's needed.

Transparency: the status above reflects the repository README. Anything planned is labelled as such; the full code and documentation are on GitHub.
